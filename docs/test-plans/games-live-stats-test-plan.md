## The 2am-Friday test

> Throttle the network to slow 3G, open a game, fire 20 taps at one player across four
> different stat types, background the app mid-sequence, reopen it, go offline, fire five
> more taps, come back online. Assert the server's final line equals the exact sum of all
> 25 actions, and that the UI never showed a number it later silently revoked.

That single test covers faults 1, 2 and 3 of SM-1, the SM-3 recovery path, and the queue
replay semantics. It is currently impossible to write in this repo.

## The hostile-QA test

> Mark a player DNP mid-game while a stat write for that same player is still in flight.

Today: the in-flight write lands after the DNP toggle, `stats` is already null locally, and
the next box-score edit commits an all-zero line over real numbers. Nothing detects it.

## Flakiness risks

- Any test asserting on wall-clock save timestamps (`Saved 7:41 PM` in the SM-1 spec is the
  client clock — inject it, do not read `Date.now()` in the component).
- Queue replay tests depend on ordering; assert on the final state, not on call sequence.
- Backend tests already use a Postgres service container in CI, so 6, 7, 10-12 need no new
  infrastructure.
